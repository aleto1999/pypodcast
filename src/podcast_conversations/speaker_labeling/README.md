# Speaker Labeling Package

## Overview

The `speaker_labeling` package provides a comprehensive 5-stage pipeline for identifying and naming speakers in podcast transcripts. Its primary goal is to replace generic speaker IDs (e.g., `SPEAKER_00`, `SPEAKER_01`) generated by diarization tools with actual speaker names (e.g., "Joe Rogan", "Brian Redban"). This enables more meaningful and interpretable analysis of conversational content.

The pipeline combines metadata extraction, natural language processing (NLP) techniques, cross-episode analysis, and advanced role classification (including optional Large Language Model-based classification) with heuristic voice-name mapping to achieve robust speaker identification.

## Features

-   **5-Stage Pipeline**: A structured approach covering metadata, NER, cross-episode analysis, role classification, and voice-name mapping.
-   **Metadata Extraction**: Infers speaker names from RSS feeds, episode filenames, and podcast folder names.
-   **Transcript NER**: Utilizes spaCy's Named Entity Recognition and custom pattern matching to identify person names within transcript text.
-   **Cross-Episode Analysis**: Analyzes speaker consistency and speaking patterns across multiple episodes of a podcast to identify recurring hosts.
-   **Flexible Role Classification**:
    -   **Heuristic**: Rule-based classification for quick and efficient role assignment (HOST, GUEST, NEITHER).
    -   **LLM API**: Integrates with OpenAI API (e.g., GPT-4o-mini) for advanced, context-aware role classification.
    -   **Local LLM**: Supports local transformer models (e.g., Llama 3) with CUDA/GPU acceleration and quantization for privacy and performance.
-   **Voice-Name Mapping**: Heuristically maps identified names to specific speaker IDs based on self-introductions, direct mentions, speaking time, and cross-episode patterns.
-   **Labeled Transcripts**: Outputs enriched JSON transcripts with `speaker_name` and `speaker_role` fields for each segment.
-   **Comprehensive Summaries**: Generates detailed Markdown summary reports for the overall pipeline run and for individual podcasts.
-   **Configuration**: Highly configurable with options for LLM models, quantization, parallel processing, and confidence thresholds.
-   **Robust Error Handling**: Provides logging and graceful error management throughout the pipeline.

## Pipeline Overview

The speaker labeling process follows a modular, multi-stage pipeline:

1.  **Metadata Extraction (`MetadataExtractor`)**: Extracts initial speaker name hints from RSS feeds, filenames, and podcast folder names.
2.  **Transcript NER (`TranscriptNERExtractor`)**: Scans transcript text using spaCy and regex patterns to find additional person names, especially in episode introductions.
3.  **Cross-Episode Analysis (`CrossEpisodeAnalyzer`)**: Identifies consistent speaker patterns across all episodes of a podcast to determine probable host speaker IDs.
4.  **Role Classification (`HeuristicRoleClassifier`, `LLMRoleClassifier`, `LocalLLMRoleClassifier`)**: Classifies the extracted names as `HOST`, `GUEST`, or `NEITHER` using rule-based logic or advanced LLMs with contextual prompting.
5.  **Voice-Name Mapping (`VoiceNameMapper`)**: Applies a set of heuristics to definitively map the classified names to the generic `SPEAKER_XX` IDs within each episode.
6.  **Transcript Labeling (`TranscriptLabeler`)**: Injects the identified speaker names and roles into the transcript segments.
7.  **Summary Generation (`SummaryGenerator`)**: Creates detailed markdown reports summarizing the labeling process and results.

## Components

### 1. `MetadataExtractor` (`metadata_extractor.py`)

Extracts speaker names from various metadata sources:
-   **RSS Feed**: Uses `rss_metadata.json` files from `outputs/rss_metadata/` (generated by the speaker labeling pipeline stage 1) to get host/guest hints from podcast/episode titles and descriptions. (Highest confidence)
-   **Podcast Folder Name**: Uses a predefined `KNOWN_HOSTS` map (e.g., "the_joe_rogan_experience" -> "Joe Rogan").
-   **Episode Filename**: Parses names embedded in filenames (e.g., "1_brian_redban.json" -> "Brian Redban").

These hints provide high-confidence initial name candidates.

### 2. `TranscriptNERExtractor` (`transcript_ner.py`)

Identifies additional names directly from the transcript text:
-   **spaCy NER**: Uses pre-trained spaCy models (`en_core_web_sm` or `en_core_web_lg`) to detect `PERSON` entities.
-   **Pattern Matching**: Employs regex patterns to capture common introduction phrases (e.g., "I'm [NAME]", "Welcome [NAME]").
-   **Context-Aware**: Focuses on the initial words of a transcript (first ~500 words) where introductions are most likely to occur.
-   **Deduplication**: Merges duplicate name detections and boosts confidence for names found by multiple methods.

### 3. `CrossEpisodeAnalyzer` (`cross_episode_analyzer.py`)

Analyzes speaking patterns across all episodes of a podcast series to robustly identify the host:
-   **Speaker Presence**: Tracks which speaker IDs appear in most episodes.
-   **Speaking Time Consistency**: Measures the consistency of a speaker's speaking time proportion across episodes.
-   **Rank-Based Identification**: The host is typically the speaker with a consistent high speaking time rank (e.g., `SPEAKER_00` or `SPEAKER_01` in most episodes).
-   **Host Candidate**: Returns a `HostCandidate` indicating the expected rank and confidence.

### 4. `RoleClassifier` (`role_classifier.py`)

Determines the role (HOST, GUEST, NEITHER) of each extracted name based on various signals:
-   **HeuristicRoleClassifier**: A rule-based classifier that uses simple patterns and metadata hints (e.g., name in podcast title, known host lists).
-   **LLMRoleClassifier**: Leverages a remote LLM (e.g., OpenAI's `gpt-4o-mini`) to classify roles based on rich contextual prompts. Requires an API key.
-   **LocalLLMRoleClassifier**: Utilizes a local HuggingFace transformer model (e.g., Llama 3) for role classification. Supports CUDA GPU acceleration, auto-model selection based on VRAM, and 4-bit/8-bit quantization for memory efficiency.

The pipeline prioritizes local LLM (if CUDA available), then LLM API (if API key available), falling back to heuristics if neither is configured.

### 5. `VoiceNameMapper` (`voice_name_mapper.py`)

Assigns the classified speaker names to the generic `SPEAKER_XX` IDs in the transcript:
-   **Self-Introduction**: Identifies speaker IDs that introduce themselves using a classified name (e.g., "I'm [NAME]").
-   **Direct Mention**: Maps a guest to the speaker ID who is introduced by another speaker using their name.
-   **Cross-Episode Pattern**: Uses the host rank identified by `CrossEpisodeAnalyzer` to assign the host name.
-   **Speaking Time Rank**: Assigns HOST to the speaker with most speaking time, GUEST to the second, etc.
-   **Fallback**: Assigns to the first available speaker if other heuristics fail.

### 6. `TranscriptLabeler` (`voice_name_mapper.py`)

A utility class that applies the generated speaker mappings to the original transcript data structure, enriching each segment with `speaker_name` and `speaker_role`.

### 7. `SummaryGenerator` (`summary_generator.py`)

Generates comprehensive Markdown summary reports:
-   **General Summary**: Provides an overview of the entire pipeline run, including total podcasts/episodes processed, labeling rates, average confidence, and distributions of assignment methods and roles.
-   **Per-Show Summaries**: Detailed reports for each podcast, including identified speakers, episode-level labeling status, and assignment method breakdowns.

## Usage

The speaker labeling pipeline is orchestrated via the `SpeakerLabelingPipeline` class and can be run through a dedicated CLI script.

### Command Line Interface

To run the full speaker labeling pipeline:

```bash
uv run python scripts/run_speaker_labeling_pipeline.py [OPTIONS]
```

**Options**:

-   `--podcast PODCAST_NAME`: Process a specific podcast by its folder name.
-   `--all`: Process all podcasts found in the input directory.
-   `--input-dir PATH`: Path to the input directory containing post-processed transcripts (default: `outputs/transcripts_with_speakers_postprocessed`).
-   `--output-dir PATH`: Path to the output directory for labeled transcripts (default: `outputs/transcripts_with_speaker_names`).
-   `--rss-dir PATH`: Path to the directory containing RSS metadata JSON files (optional, recommended for better accuracy).
-   `--use-llm`: Enable LLM API for role classification (requires `OPENAI_API_KEY` environment variable).
-   `--llm-model MODEL_NAME`: Specify the OpenAI model to use (default: `gpt-4o-mini`).
-   `--use-local-llm`: Enable local transformers model (CUDA required) for role classification.
-   `--local-model MODEL_NAME`: HuggingFace model name for local inference (e.g., `meta-llama/Llama-3-8B-Instruct`). If `None`, auto-selects based on GPU VRAM.
-   `--load-in-4bit`: Use 4-bit quantization for local LLM (NVIDIA GPUs).
-   `--load-in-8bit`: Use 8-bit quantization for local LLM (NVIDIA GPUs).
-   `--dry-run`: Perform a dry run without saving any output files.
-   `--min-confidence FLOAT`: Minimum confidence for speaker assignments (0.0-1.0, default: `0.5`).

**Example Usage**:

```bash
# Basic usage with heuristic classification (fastest)
uv run python scripts/run_speaker_labeling_pipeline.py --podcast "the_joe_rogan_experience"

# Process all podcasts using OpenAI API (requires OPENAI_API_KEY env var)
uv run python scripts/run_speaker_labeling_pipeline.py --all --use-llm

# Process a specific podcast using a local CUDA LLM with 4-bit quantization
uv run python scripts/run_speaker_labeling_pipeline.py \
    --podcast "lex_fridman_podcast" \
    --use-local-llm \
    --local-model "meta-llama/Llama-3-8B-Instruct" \
    --load-in-4bit \
    --input-dir "outputs/transcripts_with_speakers_postprocessed" \
    --output-dir "outputs/final_labeled_transcripts"

# Dry run to see what would be processed
uv run python scripts/run_speaker_labeling_pipeline.py --podcast "the_daily" --dry-run
```

**Note**: The pipeline automatically downloads RSS metadata in stage 1. Use `--skip-rss-download` if you already have RSS metadata in `outputs/rss_metadata/`.

### Python API

```python
import asyncio
from pathlib import Path
from podcast_conversations.speaker_labeling import SpeakerLabelingPipeline, PipelineConfig

async def main():
    # Configure the pipeline
    config = PipelineConfig(
        input_dir=Path("outputs/transcripts_with_speakers_postprocessed"),
        output_dir=Path("outputs/transcripts_with_speaker_names"),
        rss_metadata_dir=Path("outputs/rss_metadata"),
        use_llm=True,  # Set to True to use OpenAI API
        llm_model="gpt-4o-mini",
        # use_local_llm=True, # Set to True to use local CUDA LLM
        # local_model="meta-llama/Llama-3-8B-Instruct",
        # load_in_4bit=True,
    )

    pipeline = SpeakerLabelingPipeline(config)
    summary = await pipeline.run()

    print(f"Pipeline finished. Total episodes processed: {summary.total_episodes_processed}")
    print(f"Average confidence: {summary.average_confidence:.2f}")

if __name__ == "__main__":
    asyncio.run(main())
```

## Configuration

The pipeline's behavior can be controlled via the `PipelineConfig` Pydantic model. Key configurable aspects include:

-   **Input/Output Paths**: `input_dir`, `output_dir`, `rss_metadata_dir`.
-   **Role Classifier Selection**: `use_llm`, `llm_model`, `use_local_llm`, `local_model`, `load_in_4bit`, `load_in_8bit`.
-   **Performance**: `max_workers` (for parallel processing), `batch_size`.
-   **Control Flow**: `skip_existing` (to skip already processed files), `min_confidence` (threshold for assigning names).

## Troubleshooting

### SpaCy Model Not Found

**Error:** `OSError: [E050] Can't find model 'en_core_web_sm'.` or similar.

**Fix:** Ensure the spaCy model is installed and downloaded.
```bash
uv pip install spacy
uv run python -m spacy download en_core_web_sm # or en_core_web_lg
```

### Local LLM Requirements

**Error:** `ImportError: transformers and torch required for local LLM.`

**Fix:** Install necessary packages.
```bash
uv pip install transformers torch accelerate
# For quantization (NVIDIA only):
uv pip install bitsandbytes
```

### OpenAI API Key Missing

**Warning:** `No API key provided, falling back to heuristic classification`

**Fix:** Set the `OPENAI_API_KEY` environment variable or provide it directly to the `LLMRoleClassifier`.

### CUDA Not Available

**Error:** `RuntimeError: CUDA is not available. Install PyTorch with CUDA support.`

**Fix:** If attempting to use local LLMs with `--use-local-llm`, ensure your PyTorch installation supports CUDA and your system has a compatible NVIDIA GPU. Otherwise, use `use_llm` (API-based) or rely on heuristics.
